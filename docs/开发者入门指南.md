## 1. 项目全景：这一套东西是什么

```
miniprogram-dev\
├── README.md                  # 平台总览与 FAQ
├── docs\
│   └── 开发者入门指南.md      # 本文档
├── tools\
│   ├── gen-icons.js           # tabBar 图标生成脚本（零依赖）
│   └── wechat_devtools_*.exe  # 微信开发者工具安装包

│   └── package.json

    ├── app.json / app.js / app.wxss / sitemap.json
    ├── project.config.json    # AppID + 云函数根目录 + 编译设置
    ├── utils\
    │   ├── config.js          # 数据源开关（cloud / mock）+ 云环境 ID
    │   ├── data.js            # 统一入口：按开关分发

    │   └── request.js         # wx.request 的 Promise 封装
```

## 2. 最小可运行项目：哪些文件是必须的

**结论：`app.json` + `app.js` + 每个页面的 `.js` + `.wxml`，共 4 类文件就能跑。**
开发阶段再加一个 `project.config.json`（工具识别项目用）。

| 文件 | 运行必需 | 开发必需 | 作用 |
|---|---|---|---|
| `app.json` | ✅ | ✅ | 全局配置：页面注册、窗口样式、tabBar、分包 |
| `app.js` | ✅ | ✅ | 应用入口：`App()` 生命周期、`globalData` |
| `pages/x/x.js` | ✅ | ✅ | 页面逻辑（`Page()`） |
| `pages/x/x.wxml` | ✅ | ✅ | 页面结构 |
| `project.config.json` | ❌ 不进代码包 | ✅ | 工具识别项目、绑定 AppID、编译设置 |
| `pages/x/x.wxss` | ❌ | ❌ | 页面样式（缺省 = 无样式） |
| `pages/x/x.json` | ❌ | ❌ | 页面配置（标题、下拉刷新、注册组件） |
| `app.wxss` | ❌ | ❌ | 全局样式 |
| `sitemap.json` | ❌ | ❌ | 微信搜索索引规则（不写 = 默认全允许） |
| `project.private.config.json` | ❌ 不进代码包 | ❌ | 工具生成的本地个人设置 |
| tabBar 图标 png | 按需 | 按需 | **配了 `iconPath` 就必须存在**，否则编译报错 |
| `utils/` `images/` `components/` | 按需 | 按需 | 自定义目录，路径随意 |

### 最小结构示例

```
miniprogram/
├── app.js                  # App({})
├── app.json                # {"pages": ["pages/index/index"]}
└── pages/
    └── index/
        ├── index.js        # Page({})
        └── index.wxml      # <view>Hello</view>
```

> 记忆法：**「app 双件套 + 页面双件套 + 开发配置一件」**。

## 3. 各文件职责详解

### 3.1 app.json —— 全局配置（最重要）

```json
{
  "pages": ["pages/index/index", "pages/list/list"],
  "window": { "navigationBarTitleText": "小记", "navigationBarTextStyle": "white" },
  "tabBar": { "list": [ { "pagePath": "pages/index/index", "text": "首页" } ] },
  "style": "v2",
  "sitemapLocation": "sitemap.json"
}
```

要点：
- `pages` 数组**第一项就是启动首页**；每个路径必须真实存在对应的 `.js`/`.wxml`
- `tabBar` 最少 2 个、最多 5 个页面；图标必须本地 png（推荐 81×81）
- **必须是纯 JSON，不能写注释**
- `project.config.json` 容忍注释，但 `app.json` 不容忍
- 页面级配置（如 `enablePullDownRefresh`）写在页面的 `.json` 里，不能写在这里的页面对象中

### 3.2 app.js —— 应用入口

```js
App({
  onLaunch() { /* 启动一次：初始化、读缓存 */ },
  onShow()    { /* 前台切换 */ },
  onHide()    { /* 后台切换 */ },
  globalData: { version: '1.0.0' },
});
```

### 3.3 app.wxss —— 全局样式

相当于网页的全局 CSS。`page` 选择器相当于 `<body>`。Demo 里定义了 `.card`、`.container`、`.btn-primary` 等公共类。

### 3.4 页面四件套

| 文件 | 必需 | 说明 |
|---|---|---|
| `x.js` | ✅ | `Page({ data, onLoad, ... })` |
| `x.wxml` | ✅ | 结构，`{{ }}` 绑定数据，`wx:for` / `wx:if` |
| `x.wxss` | 可选 | 只作用于本页面 |
| `x.json` | 可选 | 本页配置，如 `{"navigationBarTitleText": "详情", "enablePullDownRefresh": true}` |

**常用生命周期：**

| 钩子 | 时机 |
|---|---|
| `onLoad(options)` | 页面加载一次：接收 url 参数、请求初始数据 |
| `onShow()` | 每次显示：刷新状态 |
| `onReady()` | 首次渲染完成 |
| `onHide()` | 页面隐藏 |
| `onUnload()` | 页面销毁 |

**改数据必须 `this.setData()`**——直接给 `this.data` 赋值不会更新界面。`setData` 越精确越好（大对象整树重渲染会卡）。

**页面传参**：`wx.navigateTo({ url: '/pages/detail/detail?id=3' })` → 目标页 `onLoad(options)` 里取 `options.id`。复杂对象建议只传 id，再查详情。

### 3.5 project.config.json —— 开发配置（不进代码包）

| 字段 | 含义 |
|---|---|
| `appid` | 小程序唯一身份，**必须是小程序类型的正式/测试 AppID** |
| `compileType` | `miniprogram`（本项固定） |
| `setting.urlCheck` | `false` = 不校验请求域名（本地 mock 靠它） |
| `setting.es6` / `enhance` | 语法转换与增强编译 |

⚠️ **重要：开发者工具运行时会用自身缓存回写这个文件**。改 AppID 正确姿势是**在工具里改**（详情 → 基本信息 → AppID → 修改），或关闭工具后改文件再打开；开着工具直接改文件可能被覆盖。

### 3.6 project.private.config.json —— 工具生成的本地设置

记录 `libVersion`（基础库版本）、是否热重载等个人偏好。**不要手写、不要提交到代码仓库**，删掉后工具会重新生成。

### 3.7 sitemap.json —— 搜索索引

```json
{ "rules": [{ "action": "allow", "page": "*" }] }
```
不写这个文件也能运行（默认全部允许被微信搜索索引）；写了就要在 `app.json` 里用 `sitemapLocation` 指过去。

### 3.8 utils/ —— 数据访问层

页面只 require `utils/data.js`，由 `config.js` 的 `DATA_SOURCE` 决定走哪条路：

```
页面 → utils/data.js
        ├── cloud-api.js  → wx.cloud.callFunction('articles', ...)   （默认）
        └── mock-api.js   → wx.request('http://<局域网IP>:3001/...')  （本地）
```

- `request.js` 是 mock 模式的 `wx.request` Promise 封装（统一 baseUrl、超时、业务码）
- `cloud-api.js` 是云函数封装（统一 action、错误提示），两者对外接口完全一致
- 切换数据源只改 `config.js` 一行，页面代码零改动

```js
// utils/request.js（mock 模式）
const { MOCK_BASE_URL } = require('./config');
const BASE_URL = MOCK_BASE_URL;
function request(path, opts = {}) {
  return new Promise((resolve, reject) => {
    wx.request({
      url: BASE_URL + path,
      ...opts,
      success(res) {
        if (res.statusCode === 200 && res.data.code === 0) resolve(res.data.data);
        else reject(new Error(res.data?.message || '请求失败'));
      },
      fail: reject,
    });
  });
}
module.exports = { request, BASE_URL };
```

### 3.9 images/ 与 tabBar 图标

- 格式必须是**本地 png**（不支持网络图片）
- 推荐 81×81，普通态/选中态各一张
- 本项目由 `node tools/gen-icons.js` 零依赖生成，改颜色/形状后重新运行即可

### 3.10 进阶（按需再学）

- **自定义组件**：`components/名字/名字.json` 里写 `{"component": true}`，页面 json 里 `usingComponents` 注册
- **分包**：页面多、主包超 2MB 时用 `subpackages` 拆分
- **Canvas 2D 游戏**：页面里用 `<canvas type="2d">` + `canvas.requestAnimationFrame` 就能跑游戏循环；独立小游戏工程（`game.js`/`game.json`）需要小游戏账号（企业资质 + 版号），本项目把游戏放在 `pages/game`
- **云开发**：`wx.cloud.init()` + 云函数/云数据库，免服务器和域名备案（个人主体可用）；本项目已默认接入，详见 3.11

### 3.11 云开发架构（本项目已默认启用）

- 云函数 `cloudfunctions/articles` 用 `event.action` 分发：`ping` / `list` / `detail` / `seed`
- 云数据库集合 `articles` 由 `seed` 自动创建并写入 10 条示例（幂等）
- 客户端 `utils/cloud-api.js` 统一调用 `wx.cloud.callFunction`
- 好处：不需要服务器、不需要域名备案，手机体验版脱离电脑也能用
- 环境 ID 配置在 `utils/config.js` 的 `CLOUD_ENV`

## 4. 开发流程（本项目实操版）

```
启动 mock → 打开工具 → 模拟器调试 → 真机预览 → 上传 → 体验版 → 手机使用
```

### 4.1 启动 Mock 服务

```bash
cd mock-server
npm start
```

- 端口 3001，监听 `0.0.0.0`（允许手机访问）
- 启动日志会打印**本机地址**和**局域网地址**，后者要与 `utils/request.js` 的 `BASE_URL` 一致
- 首次运行 Windows 防火墙弹窗要点「允许访问」

### 4.2 导入项目

1. 双击安装 `tools\` 里的开发者工具（Stable v2.01.2510260）
2. 微信扫码登录——**必须是小程序的管理员或项目成员**
3. 「导入项目」→ 目录选 `demo-app` → 确认 AppID → 导入

### 4.3 模拟器调试

- 改代码自动编译；也可点工具栏「编译」手动重编
- 调试面板：Console（日志）、AppData（页面 data）、Storage（缓存）、Network（请求）
- 首页「接口状态」卡片可快速自检 mock 是否连通

### 4.4 真机预览

1. 手机与电脑连**同一 Wi-Fi**
2. 点「预览」→ 生成二维码 → 手机微信扫码
3. 列表页要能出数据，取决于 `utils/request.js` 的 `BASE_URL` 是否指向**电脑局域网 IP**（当前预置 `192.168.31.56`）

> 电脑 IP 变了：`mock-server` 启动日志会打印新 IP，同步改 `BASE_URL`，重新「预览」。

### 4.5 上传 → 体验版 → 手机

1. 工具右上角「上传」→ 版本号（如 `1.0.0`）+ 备注 → 确定
2. 登录 **mp.weixin.qq.com**（管理员微信）→「版本管理」
3. 开发版本 →「选为体验版」→ 生成体验版二维码
4. 手机扫码 → 小程序进入手机小程序列表，可长期使用

### 4.6 关于 AppID（重点，别踩坑）

- **测试号**（沙箱自动发放）：能开发调试、真机预览，**永远不能上传/发布**
- **公众号 AppID**：开发者工具会报 `invalid app type`（不是小程序类型），不能用
- **正式小程序 AppID**：全流程可用；登录微信必须是**管理员或开发者**，否则报 `-80002 登录用户不是该小程序的开发者`
- 换 AppID 的正确顺序：**先在小程序后台确认权限 → 再在工具里修改**；顺序反了工具会回退到旧 AppID

### 4.7 云开发部署（默认模式）

1. 确认 `utils/config.js` 的 `CLOUD_ENV` 与环境 ID 一致（当前 `cloud1-d8g774cfa69b034d6`）
2. **重启工具**让 `cloudfunctionRoot` 生效 → 右键 `cloudfunctions/articles` →「上传并部署：云端安装依赖」
3. 编译 → 进入「关于」页 → 点「初始化示例数据」（自动建集合并写入 10 条数据）
4. 之后手机体验版**无需电脑**：数据走云函数 `articles`

> 切回本地 mock：把 `DATA_SOURCE` 改为 `'mock'` 并在 `mock-server` 执行 `npm start`，页面零改动。

## 5. 常见错误速查表

| 现象 | 原因 | 解决 |
|---|---|---|
| `不在以下 request 合法域名列表中` | 请求域名未配白名单 | 工具「详情 → 本地设置」勾选不校验域名；本项目已预置 `urlCheck:false` |
| 列表页「网络异常」 | mock 没启动 / 端口被占 | `cd mock-server && npm start` |
| 真机预览没数据 | 手机与电脑不同 Wi-Fi / IP 变了 / 防火墙拦截 | 连同一 Wi-Fi；核对 `BASE_URL`；放行 3001 端口 |
| `invalid app type` / `AppID 不是小程序` | 用了公众号或错误类型 AppID | 注册「小程序」类型账号，重新获取 AppID |
| `-80002 登录用户不是该小程序的开发者` | 工具登录微信无该小程序权限 | 后台「管理 → 成员管理」添加开发者，或换管理员微信登录 |
| 测试号提示「不支持上传」 | 测试号无上传能力 | 换正式小程序 AppID |
| 编译报错但没提示具体页面 | `pages` 里注册了不存在的文件 | 检查路径拼写/大小写/文件是否齐全 |
| tabBar 报错 | 图标缺失、非 png、尺寸异常 | 补齐 81×81 png，或先去掉 `iconPath` 用纯文字 |
| 改 AppID 后又变回旧的 | 工具缓存回写 | 在工具里改（详情 → AppID → 修改），不要直接改文件 |
| `app.json` 解析失败 | 写了注释或多余逗号 | 用纯 JSON；可用 JSON 校验工具检查 |
| 云函数调用失败 | 未部署或函数名不对 | 右键 `cloudfunctions/articles` → 上传并部署 |
| 集合 `articles` 不存在 | 未初始化 | 关于页点「初始化示例数据」；或在云开发控制台手动建集合 |
| 列表页有标题但没数据 | 未执行 seed | 关于页点「初始化示例数据」 |

## 6. 学习路径建议

1. **通读 Demo**：`pages/index`（生命周期/switchTab）→ `pages/list`（分页/下拉刷新/传参）→ `pages/detail`（onLoad 参数/动态标题）→ `pages/about`（系统信息 API）
2. **动手改**：给列表页加搜索框（用 mock 的 `keyword` 参数）；给详情页加「收藏」按钮（`wx.setStorageSync`）
3. **加接口**：在 `mock-server/server.js` 写一个 `POST /api/articles`，再做个新建文章表单页
4. **组件化**：把文章卡片抽成 `components/article-card`
5. **扩展云函数**：给 `cloudfunctions/articles` 加 `create` action，实现真正的"新建文章"

## 附：术语表

| 术语 | 含义 |
|---|---|
| AppID | 小程序唯一身份标识，`wx` 开头 18 位 |
| AppSecret | 服务端调用微信接口的密钥，**绝不放进小程序代码** |
| 基础库 | 手机微信内置的小程序运行环境版本，决定可用 API |
| rpx | 响应式单位，任何屏幕宽度都等于 750rpx |
| 合法域名 | 小程序可请求的 HTTPS 域名白名单（正式环境强制） |
| 体验版 | 上传后不审核、指定成员可用的版本 |
| 分包 | 把代码拆成多个包按需加载，绕过单包 2MB 限制 |
